# 实施计划：一键搭建日本双线路节点订阅

## 阶段 1：后端建模与组合编排

- [ ] 新增组合请求 DTO、Service 接口方法和受保护的 POST Controller 接口。
- [ ] 抽取六协议组的“按逻辑键查找/创建/复用” helper，支持 `landingId = null` 的直连组和指定落地的中转组。
- [ ] 抽取落地链接的规范化、查找/复用和校验逻辑，避免重复创建同一新加坡落地。
- [ ] 实现组合流程：校验日本节点 → 复用/创建新加坡落地 → 确保直连 6 协议 → 确保中转 6 协议 → 一次推送日本 Sing-box → 返回汇总。
- [ ] 保留旧的一键直连/中转接口请求和创建语义；公共 helper 只在不改变旧行为的范围内复用。
- [ ] 对同一日本节点和落地链接增加请求级去重，避免并发双击造成重复组。
- [ ] 为失败路径增加补偿清理和阶段错误信息；验证不会误删操作前已有的协议、落地或转发。
- [ ] 复用现有 `assignSelf` 相关能力，确保双线路授权可重复调用且不复制凭证/GOST 转发。

## 阶段 2：前端操作与订阅入口

- [ ] 在 API 层增加组合接口的类型化请求/响应，并将其加入慢请求路径。
- [ ] 在中转管理页增加“一键搭建双线路”弹窗，复用节点、落地链接、名称和 SNI 字段。
- [ ] 默认勾选“同时开通我自己”；组合接口成功后按 direct/relay 两组调用现有自用分配，展示分阶段结果。
- [ ] 完成成功、解析失败、推送失败、直连授权失败、中转授权失败的可诊断提示，并刷新协议/线路/订阅数据。
- [ ] 保留现有单独“一键搭建整机协议”“一键搭中转”和普通用户分配入口。

## 阶段 3：回归验证

- [ ] 静态检查组合代码不新增端口一一映射逻辑，不把新加坡 6 个协议端口复制到日本 GOST 转发。
- [ ] 首次执行、重复执行、只缺一部分协议、已有同链接落地、失败重试分别验证幂等性。
- [ ] 验证日本 direct 六协议保持本机出网，日本 relay 六协议共用同一新加坡落地。
- [ ] 验证当前用户两组授权后 `my-lines` 为 2 条、每条 6 协议，聚合订阅为 12 协议。
- [ ] 验证删除/停用/续费/流量与到期行为在两组之间互不串线。
- [ ] 运行 `cd springboot-backend && mvn clean package -DskipTests`、`cd vite-frontend && npm run lint` 和 `npm run build`。
- [ ] 使用真实接口/测试节点做一次端到端回归，并记录配置前后协议数、落地 ID、线路数和订阅链接数。

## 实施约束与回滚点

- 默认不改数据库 schema；如果实现中需要唯一约束或新列，暂停编码并先补充迁移设计。
- 不删除旧接口和旧页面，组合入口可以独立回滚；公共 helper 出现兼容问题时优先恢复旧接口路径，再单独修正组合路径。
- 不提交用户现有的无关工作区变更（`.agents/`、`.codex/` 及其他与本任务无关修改）。
