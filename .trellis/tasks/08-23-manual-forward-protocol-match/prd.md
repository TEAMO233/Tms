# 手动转发自动匹配协议凭证

## Goal

用户在“转发管理”里为已经存在的协议创建手动转发时，只填写目标协议的本机地址和端口，就能在单条链接和转发聚合订阅中得到可直接使用的客户端协议链接，不再把新加坡节点的原始分享链接复制出来后手动改成日本入口地址和入口端口。

## Background and confirmed facts

- 转发管理的目标协议按钮已经能从目标节点的 `Inbound.listenPort` 生成 `127.0.0.1:<端口>`，当前逻辑见 `vite-frontend/src/pages/forward.tsx:616-623`、`1833-1849`。
- 目前后端生成手动转发链接时只读取用户手填的 `Forward.sourceLink`；`Forward.remoteAddr` 只用于 Gost 转发目标，见 `springboot-backend/src/main/java/com/admin/service/impl/ForwardServiceImpl.java:959-1020`。
- 协议类型、TLS/Reality 参数和监听端口在 `Inbound` 中；VLESS/VMess/Trojan/Hysteria2/TUIC/AnyTLS 的用户凭证在对应用户的 `InboundUser` 中，不能仅凭 `127.0.0.1:<端口>` 猜出凭证。已分配协议或点击“我自己用”后，凭证由现有分配流程创建，见 `springboot-backend/src/main/java/com/admin/entity/Inbound.java:26-65`、`InboundUser.java:27-44`、`InboundServiceImpl.java:566-595`。
- 已有 `ClientLinkUtil.buildInboundLink(...)` 统一拼装“我的订阅”使用的协议格式，见 `springboot-backend/src/main/java/com/admin/common/utils/ClientLinkUtil.java:100-163`；因此新逻辑应复用现有协议链接生成规则。
- 端口转发的目标节点是隧道入口节点，隧道转发的目标节点是隧道出口节点；用户截图中的六条 `127.0.0.1:40000` 至 `40005` 属于可精确匹配的单目标场景。隧道类型定义见 `springboot-backend/src/main/java/com/admin/entity/Tunnel.java:27-50`。

## Requirements

1. 当一条手动转发的远程地址是单个本机目标（`127.0.0.1`、`localhost` 或 `::1`）且端口与目标节点上唯一启用的 `Inbound.listenPort` 完全一致时，系统自动把它识别为该协议。
2. 自动识别后，使用该转发所属用户的启用状态 `InboundUser` 凭证生成客户端链接：客户端地址使用隧道入口节点的可用公网地址，客户端端口使用该转发的入口端口，协议参数和凭证沿用对应入站/用户配置。
3. 端口转发和隧道转发都必须按照各自的目标节点规则工作；不能把隧道入口节点误当成协议落地节点，也不能把日本入口地址写成新加坡落地地址。
4. 单条链接接口和转发聚合订阅接口使用同一套解析规则。聚合订阅中某条转发匹配不到协议或凭证时，只跳过该条并保留其它有效链接。
5. 当前转发没有对应的启用用户凭证时，不自动创建新凭证、不猜测凭证；单条链接给出明确提示，聚合订阅跳过该条。系统协议匹配成功时不要求用户填写原始协议分享链接；`sourceLink` 只作为非系统协议或匹配失败场景的兼容兜底来源。
6. 多个远程地址、端口匹配不唯一、协议已停用或用户凭证已停用时，不自动猜测协议，维持现有转发功能，并按第 5 条处理链接生成。
7. 已由协议分配流程直接关联的自动转发继续优先使用其现有 `InboundUser.gostForwardId` 关系；本需求只补齐手动转发的自动识别，不改变现有自动分配和“我的订阅”行为。
8. 转发管理表单的说明文案应反映：匹配到系统协议且用户已有凭证时不必填写原始分享链接；原始链接仅作为未匹配协议的备用方式。

## Acceptance Criteria

- [x] 对用户已经分配过协议凭证的六条手动转发（目标分别为 `127.0.0.1:40000` 至 `127.0.0.1:40005`），单条“生成链接”可以分别生成对应协议的有效链接；链接地址是日本入口节点地址，端口是各条转发的入口端口，凭证和协议参数来自新加坡对应入站。
- [x] 为同一用户生成转发聚合订阅时，上述六条链接均能出现在订阅内容中，客户端无需再次手工修改 IP 和端口。
- [x] 未点击“我自己用”或未被分配协议凭证时，系统不会生成无凭证链接；单条操作提示先分配/启用对应协议凭证，聚合订阅不影响其它正常转发。
- [x] 端口转发、隧道转发、停用入站、停用凭证、多目标地址和重复监听端口场景均不会错误匹配到其它协议或其它用户。
- [x] 已填有效 `sourceLink` 的旧手动转发保持可用；自动匹配不到时仍按原有 source link 生成链接，自动匹配成功时不被旧 source link 覆盖。
- [x] 前端构建和后端可执行的静态/编译检查通过，且不在日志中输出 UUID、密码或完整协议链接。

## Out of scope

- 不修改 Gost 的实际转发目标、隧道创建方式、端口分配方式或协议服务配置。
- 不在生成链接时自动调用“我自己用”或为用户新建 `InboundUser`。
- 不把多个远程地址合并成多个协议链接；多目标负载转发仍按现有 Gost 语义处理。

## Confirmed product decision

- 自动匹配成功时优先使用 TMS 当前协议和用户凭证；不要求手动填写原始链接。已有 `sourceLink` 仅在自动匹配失败时兜底，以兼容外部协议和历史转发。
