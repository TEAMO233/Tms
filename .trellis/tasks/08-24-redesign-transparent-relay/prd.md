# 重设计透明中转页面

## Goal

将管理员 `/transparent-relay` 从“顶部操作按钮 + 两列规则卡片”的信息堆叠，重新组织成更容易判断线路类型、入口/目标、运行状态和下一步操作的透明中转工作台。管理员打开页面后，应能快速区分 L4 透明中转与 HY2/TUIC 协议中转，定位异常规则，并继续完成创建、批量创建、聚合订阅、编辑、暂停/恢复、节点状态和删除等操作。

## Background / Confirmed Facts

- 页面实现位于 `vite-frontend/src/pages/transparent-relay.tsx`，当前页面同时管理 L4 透明中转和 `udp_quic` HY2/TUIC 协议中转。
- 当前页面通过 `getTransparentRelayList()`、`getNodeList()`、`getTunnelList()`、`getForwardList()` 和 `getInboundList()` 并行加载展示与表单选项数据；节点状态通过 `getTransparentRelayStatus()` 单独查询。
- 当前已有业务动作：刷新、复制聚合订阅、一键添加所有、创建 HY2/TUIC 协议中转、新增/编辑 L4 透明中转、暂停/恢复、节点状态、删除，以及多个表单和状态详情弹窗。
- 当前数据类型位于 `vite-frontend/src/types/index.ts`：`TransparentRelay` 区分 `relayType: "l4" | "udp_quic"`，并包含入口节点、端口、目标、协议、状态、错误和协议中转关联 ID。
- 用户提供的透明中转截图是本轮视觉参考，目标为深色 TMS 管理面板：左侧固定导航，顶部操作区，警示说明，规则卡片和明显的启用/暂停状态。
- Product Design brief 默认保留现有完整交互和 API 契约，只重做页面视觉层级、列表/卡片组织、状态表达和响应式布局；不把截图中的示例数据写入产品。

## Requirements

### R1. 保持功能和数据契约

- 不修改透明中转相关 API、DTO、`TransparentRelay` 类型和后端行为。
- 保留所有现有操作、加载态、错误 toast、确认删除、表单校验、提交 loading、状态详情弹窗和聚合订阅复制。
- `l4` 与 `udp_quic` 的业务差异必须继续清晰表达：协议中转不显示不适用的编辑/暂停/节点状态/删除动作，并保留当前指引文案。

### R2. 重建页面信息层级

- 顶部先呈现页面标题、用途说明和核心动作；危险/重要说明保持醒目但不压过主操作。
- 规则区优先呈现总数、按类型/状态的可扫描摘要、入口节点、目标/落地、协议类型和当前状态。
- 异常规则（应用失败、最近错误）应在规则主信息区可见，不依赖打开弹窗才能发现。
- 视觉延续 TMS 深色主题、HeroUI 语义色和现有 AdminLayout，不改全局侧边栏、顶部导航或其他页面。

### R3. 提升规则扫描和操作效率

- 桌面端优先利用横向空间呈现分组规则表面，减少原两列卡片的重复留白和卡片内部跳读；操作按钮保持稳定位置。
- 规则名称、入口地址、目标地址/落地名称、协议/类型、状态和错误文本支持长内容安全截断或换行。
- L4 与 HY2/TUIC 规则可以通过明确的分组、标签或筛选摘要快速区分，但不新增未确认的业务筛选语义。
- 节点状态详情继续使用现有弹窗，并保持流量路径、端口明细和原始 nftables 输出可查看。

### R4. 响应式与可用性

- 宽屏充分利用主内容区；常见笔记本宽度不出现横向溢出。
- `xl` 以上可使用双列规则布局；`lg` 以下优先切换为纵向规则块，移动端操作按钮仍可触达。
- 表单和状态弹窗在窄屏保持可滚动，长错误、目标地址和规则名不撑破布局。
- 保持按钮的明确中文标签、键盘/辅助技术可理解的交互语义和现有主题对比度。

## Out of Scope

- 不改后端接口、数据库、权限、API 请求顺序和业务校验规则。
- 不改 `AdminLayout`、全局导航、主题系统或其他页面。
- 不新增搜索、批量删除、排序、实时刷新、WebSocket 监控或新的统计口径。
- 不将视觉稿中的示例节点、端口、状态数量、IP 或协议结果写死到页面。

## Acceptance Criteria

- [ ] 管理员 `/transparent-relay` 在选定视觉方向下，页面标题、说明、核心动作、规则状态和规则操作形成清晰层级。
- [ ] L4 与 HY2/TUIC 规则仍能正确渲染，并保留各自适用/不适用的操作。
- [ ] 刷新、聚合订阅、一键添加、新增、编辑、暂停/恢复、节点状态、删除和所有表单弹窗行为不回归。
- [ ] 应用失败/最近错误、空列表、加载中和提交 loading 状态可见且不破坏布局。
- [ ] 桌面、窄桌面和移动端无明显横向溢出，长地址和错误文本安全展示。
- [ ] 设计 QA 对照用户截图完成，页面级 ESLint、`npm run build` 和关键交互检查通过。
